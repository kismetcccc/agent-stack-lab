## 1. 三种交付，不能互相冒充

| 交付层级 | 完成条件 | 当前边界 |
|---|---|---|
| 学习型 v1 源码/文档交付 | 完成本页必需功能、测试、文档与发布核验；符合计划的有限范围 | 可先完成，不因可选 live 或所有生产增强未做而无限延期 |
| 正式采用开源许可证 | 在学习型交付之外，由所有者明确选择许可证及正确版权主体，再添加/核对许可原文 | **阻塞：尚未选择许可证**；公开仓库不是许可选择，不能擅自添加 MIT |
| 公网托管、生产或第三方制品分发 | 另获部署/费用/数据授权，完成对应安全、运维、容量及许可义务评审 | **未授权/未验收**；本页不自动授权部署、购买资源或发布容器镜像 |

不必为了完成隔离学习型 v1 引入 Kubernetes、HA、MFA、RAG、多 Agent、真实模型评分或新外围组件；但必须诚实列出缺失能力。确认的数据丢失、越权、假成功、秘密泄漏和无限重试缺陷不能改叫“延期”来通过。

## 6. 推送后的验收与停止条件

1. 发布负责人按既有授权只推送审核过的非敏感源码/文档；不修改仓库安全设置，不自动创建公网服务、付费资源或真实模型配置。
2. 读取远端分支，核对实际 commit 与预期文件；结果不确定时先查询，不盲目重复写操作。
3. 检查 **该 commit** 的必需 CI，等待终态；失败时在已授权范围内定位与修复，再对新 commit 复验。不能以旧绿色 run、仅单元通过或 pending 状态宣布完成。
4. 更新本页证据记录、当前报告和任务清单。声明文档修改与被测代码的关系；后来再改代码须重新验证，不悄悄把历史计数改到新提交名下。
5. 当学习型 v1 的全部必需任务达到验收、远端/CI 已核对、已知限制与剩余授权事项准确列明时，`REL-01` 收口；不因 live、K8s、生产化或完整商业分发审查仍待后续而无限扩张开发。

### 必须保留的非生产限制

单 relay/Worker 教学部署；无认证限流、MFA、邮件验证/找回；无公网 TLS/Nginx 完整加固；Kafka 内部开发明文；无 HA/长期容量保证；迁移目前只有初始 schema，不是完整升级/回退框架；跨库无共同事务、无端到端 exactly-once；Mongo 孤儿清理与完整失败工具轨迹未实现；真实 live 全栈未验收；标准 tracing、灾备与 K8s 运行/NetworkPolicy 生效未验收。具体边界见 [SECURITY](../SECURITY.md)、[模块契约](MODULE_CONTRACTS.md) 与对应实验报告。
