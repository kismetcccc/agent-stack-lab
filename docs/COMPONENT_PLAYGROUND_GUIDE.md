# 组件操作台：点按钮，直接看后端做了什么

不用先提交任务，不用理解 Outbox 或 Agent，也不用模型 Key。打开 **http://localhost:8081/**，用已有账号登录，选择「组件实验台」里的一个组件即可。

还没启动？先看[界面启动说明](UI_GUIDE.md)。已有本机栈要保留 `.env`、忽略的 `.env.compose.local` 和数据卷，按[升级说明](OPERATIONS.md#组件操作台的保留数据更新)处理；本机更新仍待协调者完成云端 CI 后验收，**本文不是已经部署或实跑的证明**。下面的输入是合成示例，“应看到”表示操作成功时的预期，不是假造截图或真实运行记录。

## 开始前记住三件事

1. **本机共享教学数据**：换一个本地账号也能看到这批 lab 数据。仍需登录、CSRF 和正确 Origin；原任务仍只属于原账号。
2. **只放练习内容**：不要放密码、个人资料、模型 Key 或重要文件。操作台使用独立表/集合/键前缀/topic，不会拿任务或账号当练习数据。
3. **看回读，不只看输入框**：编辑器里有文字不代表已经保存；红色错误不是空数据。保留页面提供的请求 ID 排查，但不要公开 cookie 或连接配置。

主页四张卡片可以任选顺序；手机可横向滑动顶部导航选择组件，操作区域向下排列。

## 练习一：MySQL 保存、修改、删除一条记录

进入 **MySQL**（`#mysql`）。这里是固定字段的记录表，不是 SQL 执行窗口。

| 步骤 | 点击/输入 | 应看到的变化 |
|---|---|---|
| 1 | 「名称」填 `第一条学习笔记`；「内容」填 `我正在学习 MySQL`，点「创建记录」 | 「已保存的记录」出现一行；有服务端生成的 ID、内容、更新时间 |
| 2 | 点「刷新列表」，或刷新浏览器页面 | 同一条记录仍从 API 读取出来，不靠浏览器内存保留 |
| 3 | 点该行「编辑」 | 服务端重新读取对象，再把内容填入编辑区；显示正在编辑的 ID |
| 4 | 把内容改成 `修改后仍能重新读取`，点「保存修改」 | 同一 ID 显示新内容；创建时间保留、更新时间更新 |
| 5 | 点该行「删除」，先点「取消」 | 记录仍在；取消没有发送删除请求 |
| 6 | 再点「删除」，确认对象名称后点「确认删除」 | 服务端确认删除，刷新列表后该行消失 |

展开「服务端返回的数据」可看完整响应：`id,name,value,created_at,updated_at`。名称去掉两端空白后 1–80 字符，内容最多 1000 字符，可为空；同名记录可以存在，辨认时看 ID。

**你学到的是**：数据通过 API 写入 MySQL `lab_records`；写入后回读、刷新后重查。它不展示任意 SQL、事务管理或索引控制台。共享编辑没有乐观锁，后提交会覆盖先提交；开始编辑后别人删除该对象会得到不存在提示，而不是偷偷重建。

## 练习二：Redis 的值真的会到期吗？

进入 **Redis**（`#redis`）。为避免覆盖别人正在演示的键，可以把下面的键名改成自己的非秘密练习名称。

1. 「键名」填 `lesson-note`，「值」填 `这句话只保存十秒`，把「过期时间（秒）」设为 `10`。
2. 点「写入并设置 TTL」。右侧应出现 **「服务端确认：键存在」**、实际读到的值、服务端观察时间，以及 **「服务端 TTL 快照」**（单位 `ms`，通常已小于 10000）。
3. 过一两秒点「再次读取」。这次请求重新访问 Redis；若期间没有覆盖，TTL 应下降。它不是把旧数字在浏览器里改小。
4. 等超过十秒。参考倒计时归零时页面会实际读取一次；也可手动点「再次读取」。成功的新响应应为 **「服务端确认：键不存在」**，完整快照为 `exists:false,value:null,ttl_ms:-2`。
5. 再次写入同键，TTL 改为 `30`、值改为 `重新写入`。这会覆盖值并重新设置 TTL，不是延续上一轮剩余时间。
6. 点「删除键」→「取消」，再读取确认仍存在；然后重新点「删除键」→「确认删除」→「再次读取」，确认缺失。过期的键再次确认删除也可成功。

> 参考倒计时只是按服务器快照做的**估算**；归零不是过期证据。只有新读取确认了当时键不存在。在共享空间中，缺失本身不能分辨过期、别人删除或从未写入；本练习要在没有其他人改该键时观察 TTL。

| 结果 | 正确理解 |
|---|---|
| `exists:true`、`ttl_ms>=0` | 观察当时存在，有实际剩余毫秒数 |
| `exists:false`、`ttl_ms=-2` | 观察当时不存在；不是 Redis 故障 |
| `ttl_ms=-1` | 键存在但无过期时间，页面如实提示异常，不伪造倒计时 |
| `redis_unavailable` | Redis 未配置/不可用或操作失败；不能说键已过期 |

键名限 1–64 位英文字母、数字、`_`、`-`；值最多 4096 UTF-8 字节；TTL 必须整数 1–3600 秒。服务端只操作 `lab:kv:` 前缀，没有全库扫描或任意命令。旧任务的 Redis 结果缓存可降级；这里是在学习 Redis 本身，失败必须显示出来。

## 练习三：MongoDB 保存不同形状的 JSON

进入 **MongoDB**（`#mongo`），把下面内容粘进「JSON 文档」，点「保存文档」：

```json
{
  "lesson": "MongoDB",
  "tags": ["JSON", "回读"],
  "completed": false,
  "notes": {"text": "这是一份教学文档"}
}
```

1. 「已保存的文档」应出现这份 JSON、服务端 ID 与更新时间。刷新列表/页面，重新读到的仍是它。
2. 点这份文档「编辑」，确认 ID；把 `completed` 改为 `true`，并删去 `notes` 字段，点「保存修改」。
3. 列表应显示新 JSON，原 `notes` 不再存在；ID、创建时间不变。**这是完整替换，不是把字段合并到旧文档。**
4. 展开「服务端返回的数据」。你写的是 `document` 内的对象，外层 `id/created_at/updated_at` 是服务端元数据，不需要在编辑器自己填写。
5. 点「删除」先取消，检查文档仍在；再次确认删除后，刷新列表应不再出现它。

想看输入错误，可暂时把 JSON 改成 `{"lesson":}`：页面应提示语法错误，不把草稿当已保存。修好后再提交；也不要使用 `{"$where":"..."}` 或 `{"a.b":1}`，这些键名会被拒绝。

**输入预算**：根必须是对象，不是数组或单个值；紧凑 JSON 最多 16 KiB UTF-8、容器深度 6、节点 200。根容器算第 1 层，object/array 加层，标量不加层；根/容器/标量值都计节点，键字符串不计。禁止非有限数、超出 signed64 的整数、非法 Unicode，以及 `$` 开头或含 `.`/NUL 的键。浏览器的大数仍有 JavaScript 精度限制，精确编号请写成字符串。

数据保存在独立 `agent_lab.lab_documents`，不影响原 Agent `results`。JSON/HTML 文本只是数据，不会执行；这里也不是 Mongo 查询或 JavaScript 控制台。

## 练习四：Kafka「发出去」和「收到」分开看

进入 **Kafka**（`#kafka`）。「消息键」填 `lesson`，「消息内容」填 `你好，Kafka 消费者`，点一次「发送消息」。

1. 页面先生成并保留 **本次发送 ID**；地址变成 `#kafka?message=<UUID>`。即使响应丢失，也用这个 ID 查，而不是盲目重发。
2. 右侧 **「生产确认」** 显示 `已获生产确认`，表示真实 delivery callback 已确认，并记录分区、offset 和确认时间。**到这里还不能说消费者收到。**
3. 观察独立的 **「消费者收取」**。Worker 实际消费并把回执提交到数据库后，才显示 `已观察到消费者收取`。
4. 核对「消费者实际收到的内容」中的 key=`lesson`、正文=`你好，Kafka 消费者`，以及消费者分区/offset。不是把输入框复制成回执。
5. 页面自动短时读取最多 20 秒；还未观察到就停止自动观察，显示可「手动刷新」。这不是失败判定，也不是模拟进度。
6. 刷新浏览器，或从「已登记的消息」选择原记录，可继续查询；点「关闭详情」只是关闭显示，不会删消息。

| 两栏组合 | 含义 |
|---|---|
| 已获生产确认 + 尚未观察到 | 有 broker 确认，尚无已提交的消费回执；不证明丢消息或 Worker 离线 |
| 已获生产确认 + 已观察到收取 | 两种证据分别存在，可核对实际收取内容和元数据 |
| 未确认 + 已观察到收取 | 可能 broker 已送达，但 API 确认保存中断；不是矛盾，不要重发来“修好” |
| 未确认 + 尚未观察到 / 网络错误 | 结果不确定，**不能断言绝未投递**；按原 ID 查询 |

「查看本次消息」/「手动刷新」只读记录，不重发。同 ID、同内容重复 POST 也只返回当前快照；同 ID 改内容返回 409。需要发送另一条消息时，主动点「开始一条新消息」；这是**新的发送**，可能与此前未确认消息重复。

topic 固定 `agent.lab.messages.v1`，消费组固定 `agent-lab-observer-v1`。它不创建 Agent 任务、不调用模型；不提供 topic/group/offset 管理、消息删除或重放。历史回执在 MySQL 保留，只证明曾经收到，不保证 Kafka broker 永久保留正文；也不是端到端 exactly-once。

## 没看到预期结果时

| 现象 | 先做什么 |
|---|---|
| 要求登录 / 会话过期 | 用已有账号重新登录；不要移除认证。注册不是每次体验的必需步骤 |
| 403 | 确认使用 `http://localhost:8081`，获取当前会话后重试；不要公开 CSRF/cookie |
| 422 / 输入提示 | 核对字段、JSON、UTF-8 字节数和 TTL；未知字段也不接受 |
| 列表空 | 只有成功读取到空列表才能说没有数据；读取失败不是空库 |
| MySQL/Mongo 写入后网络中断 | 刷新列表/按已知 ID 读取，先查事实；离开页面不等于服务端已撤销写入 |
| Kafka 未确认 | 保留发送前 ID，查询原记录；不自动生成新 ID 重发 |
| Redis/Mongo/SQL 不可用 | 记录安全错误码与请求 ID；由授权环境排障，不在有真实数据的本机随手停库或删卷 |
| UI 标记测试/演示替身 | 只能练习界面/契约，不宣称真实四组件通过；模式未知也不当作真实已连接 |
