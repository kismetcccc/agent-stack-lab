# 中文学习路线

目标不是背产品名，而是能回答：请求到了哪里？谁保存事实？哪里会失败？失败后能否恢复？每章按“观察正常行为 → 阅读代码 → 故障实验 → 复述取舍”进行。

> 当前可靠后端、可选学习界面及受限单Agent已有实现，本轮真实Compose/浏览器CI通过，见 [单Agent验收报告](AGENT_TEST_REPORT.md)；真实LLM尚未调用或验收。建议先按[界面指南](UI_GUIDE.md)提交示例，再读[单任务导读](AGENT_WALKTHROUGH.md)，最后按下方章节回看代码。新外围组件与Kubernetes继续暂停。

## 第 0 章：画出系统

先读 [README 的点餐例子](../README.md)，只解释API接单、SQL记账、Worker干活、Kafka传单、Mongo存成果、Redis显示临时提示。再读[架构](ARCHITECTURE.md)的“问题→引入→代价”表；不用一开始就读完所有高级术语。最后按需要查 [Agent.md](../Agent.md) 实施约束。

**练习**：画三条箭头：HTTP 到数据库、Outbox 到 Kafka、MongoDB 到结果引用。解释为何只有第一条里的一部分属于一个 SQL 事务。

## 第 1 章：HTTP、API 和前端状态

阅读 [API 契约](API_CONTRACT.md)，理解 202 是接受任务而非执行完成，401/403/404/409/422/503 各解决什么问题。前端只显示后端状态；刷新不能丢任务。

**练习**：对同一任务重复点击提交；断开请求后用同幂等键重试；讨论为何浏览器禁用按钮不能代替后端幂等。

## 第 2 章：身份、会话与授权

学习密码哈希、不透明会话、HttpOnly、SameSite、CSRF 和资源所有权。登录回答“你是谁”，授权回答“这个任务是不是你能读”。本地帐号 scaffold 没有找回、MFA 和公网反滥用能力。

**练习**：A、B 两个帐号，B 查询 A 的详情、events、attempts、results、agent-steps 都必须失败；删除 CSRF header 后写操作必须失败。知道 task_id 不能绕过授权。

## 第 3 章：MySQL 是账本

阅读 Task/Outbox/Inbox/Attempt 模型；理解唯一约束、事务、行锁、复合索引与稳定分页。对照 `TaskService.create/claim/finalize`。

**练习**：两条并发同键请求；解释为什么“先 select，没有再 insert”仍会竞争。用 EXPLAIN 学习索引，记录测量数据而不是声称所有查询都高效。初始 schema 入口不是完整迁移历史；后续练习加列和回滚规划。

## 第 4 章：Kafka 与异步交付

学习 topic、partition、key、consumer group、offset、至少一次、重放。再读 Outbox/Inbox。

**练习**：停止 Kafka 后创建任务，观察 pending 与未发送 outbox；恢复后应继续执行。重复投递相同 event_id，任务不能重复创建。Kafka 是日志型消息平台，不是 SQL 状态表。

## 第 5 章：长任务、租约和重试

读状态机、fence、next_attempt_at。理解“任务正在运行”也可能只是一个已经死亡的进程留下的记录。

**练习**：旧执行器暂停、租约到期、新尝试开始，然后旧执行器恢复；它不得覆盖新结果。测试适配器可精准控制时间和故障，但不能据此宣称跨容器故障实验通过。

## 第 6 章：MongoDB 和 Redis 各司其职

MongoDB 适合不同步骤/模型结果的文档结构，MySQL 负责关系约束和事务；选择来自访问模式而非“一个先进一个落后”。Redis 作为有 TTL 的提示丢失后能重建，不控制最终成功。

**练习**：停止 Redis 后执行任务仍成功；停止 MongoDB 时不得出现没有结果的成功。解释“Mongo 已写、SQL 未提交”留下的孤儿为什么不能展示。

## 第 7 章：Agent 与普通后台任务有什么不同

先跟随[单Agent导读](AGENT_WALKTHROUGH.md)提交“销量10、20、30”的示例，再读 `Model.run → run_agent → controller.next → execute_tool`。运行时已支持读文本、字面搜索和词法统计；一次决策选择一个工具或结束。默认deterministic由脚本markers控制，不是真实模型推理；live适配器已实现，但实际provider调用仍待用户私密配置、授权与单独验收。

**练习**：将搜索词从“销量”改成材料中不存在的“利润”，观察为什么脚本不再统计。对照SQL后台生命周期和Mongo成功后工具动作；运行中/失败时空动作列表不证明工具从未执行。再找出步数、字节、时间与租约限制。外部材料不能扩大工具权限，本轮不支持URL/文件读取、真实副作用或多Agent，也不记录隐藏思维链。

## 第 8 章：可观测性与排障

日志告诉你具体事件，指标告诉你总体趋势，trace 连接一个跨进程请求。task_id 和 event_id 是业务关联标识，trace_id 并非 span 自动存在的证明。

**练习**：从某个 task_id 找到发布、接收、执行与结果；测量失败率/处理时长；再实现并验证 OTel span 与 Kafka 上下文传播。启动 Grafana 不是完成观测能力。

## 第 9 章：容器与CI；Kubernetes留待后续

Compose和CI已有本轮真实执行证据；先阅读验收报告，再查看正常部署与进程重启。Kind/Kubernetes部署实验仍延期，不要求本轮掌握。区分进程存活、依赖就绪、业务成功三层证据。

**练习**：重新创建容器而保留卷，验证任务还在；学习 Deployment、Service、ConfigMap、Secret、PVC 和迁移 Job。删除集群/卷是破坏性重置，不是日常停止。

## 后续传统后端专题（计划，不冒充现成功能）

- 对象存储：附件上传、授权下载、大小限制和清理。
- 搜索：全文/向量检索、索引更新、重建和一致性延迟。
- 调度：持久化计划、到期入队、重复触发幂等；对照 CronJob。
- 缓存：已实现不可变结果TTL读缓存；后续学习命中率测量、穿透/击穿和可变数据失效竞态。
- 网关与韧性：限流、超时预算、背压、熔断的适用边界。
- 数据工程：升级迁移、慢查询、备份恢复演练、容量规划。
- 安全与交付：审计、最小权限数据库用户、密钥轮换、CI供应链、版本回滚。

每新增一个组件，要交付一个实际用途、一个故障实验和一段“不用它会怎样”的解释。
