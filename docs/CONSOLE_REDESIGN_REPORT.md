## 3. 必须保持的真实语义

1. 总览的 `/readyz` 当前不含 Redis 总体探针、Worker 活跃探针或主机指标。未检测、失败、旧快照与成功必须分开。
2. MySQL/Mongo 的编辑草稿不等于已写入；保存响应与列表回读是独立结果。
3. Redis 只查询指定键；本地参考倒计时不是服务端缺失证明，不可用也不是过期。
4. Kafka 的生产确认和实际消费回执分别呈现；按稳定 ID 查询不重发，历史回执不保证 broker 仍保留消息。
5. 关闭抽屉或导航不能撤销已被服务端接受的写入。未提交草稿、重复提交、身份切换及旧响应均须有回归验证。

## 5. 发布前发现并修复的交互问题

- 统一抽屉关闭提示不再暗示失败/未知写入没有发出，明确关闭不会撤销服务端请求。
- 未登录的任务深链接先保留登录入口，避免详情遮罩让登录不可操作。
- 快速 hash 切换、重复 URL 历史项和连续后退按最新导航意图处理，并有草稿阻止/确认回归。
- 修正学习资料中指向当前 checkout 不存在的基础设施配置链接，不把后续路线写成已有部署。
