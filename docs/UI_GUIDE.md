# 学习界面：先理解组件，再观察一次真实任务

前端是现有后端的可选学习入口，不是另一个模拟后端。视觉借鉴 [Codex 官方展示](https://openai.com/codex/) 中克制的侧栏和工作区布局；本项目与 OpenAI 官方产品没有隶属关系，不使用其品牌标识。

## 启动

需要 Docker、Compose v2。仅第一次且尚无 `.env` 时运行：

```bash
python scripts/infra-init-env.py
```

已有 `.env` 时保留它，不要为了消除提示删除凭据或数据库卷。启动可选界面：

```bash
docker compose -f compose.yaml -f compose.ui.yaml up -d --build --wait --wait-timeout 300
```

- 学习界面：**http://localhost:8081/**。
- 同源接口文档：**http://localhost:8081/docs**。
- 默认后端单独运行方式仍是 `compose.yaml` 和 8080；新增界面没有取代它。

UI 覆盖配置将 API 的允许 Origin 设为 `http://localhost:8081`。请使用这个完整地址；`127.0.0.1` 与 `localhost` 是不同 Origin，不能随意混用。启用 UI 时应从 8081 打开接口文档，不要在 8080 的 Swagger 页面发带浏览器 Origin 的写请求。命令行客户端与服务内部地址也不是同一个概念。

普通停止保留数据卷：

```bash
docker compose -f compose.yaml -f compose.ui.yaml down
```

不要在普通停止时加 `-v`。本配置仅绑定回环地址，不是公网部署方案。

## 推荐的十分钟体验顺序

1. **总览**：先看六个角色，而不是先背中间件名字。切换“提交与执行”和“查询与结果”，区分异步任务与同步查询。
2. **点组件**：阅读“解决什么问题、不负责什么、输入与输出、失败会怎样”。桌面右侧显示说明；小屏点击后定位到说明区域。
3. **比较三个数据组件**：MySQL 决定任务状态；MongoDB 保存结果文档；Redis 保存可丢弃的缓存，不可以替另两者决定任务是否成功。
4. **运行任务**：创建本地教学帐号并登录，提交一段不含秘密的示例文本。这里不是模型 API 密钥输入框。
5. **查看真实记录**：观察任务、生命周期事件、执行尝试和结果。再次查询已完成结果，比较实际返回的 Redis `cache_status`。
6. **再看可靠性细节**：理解为什么需要 Outbox、Inbox、幂等与租约。配合 [后端故障实验](FAILURE_LABS.md) 进行隔离环境演练；界面不提供停止宿主机服务的危险按钮。

## 哪些是示意，哪些是实测数据

- 架构箭头和职责说明是教学模型，不是实时网络抓包。
- `/events` 来自 MySQL 持久化生命周期记录。它能证明相应业务转换已经记录，不等于捕获了每一次网络请求。
- 任务的阶段进度不是模型完成百分比，更不是隐藏思维链。
- MySQL、MongoDB、Kafka 的实时可用性来自 `/readyz`；接口没有提供探针的组件必须显示未知或“通过任务观察”。没有数据不能画成在线。
- Redis 的 `hit/miss/unavailable/disabled` 来自一次实际结果查询，不能当作永久健康承诺。
- 默认模型是 `deterministic` 测试适配器，不会调用真实模型；真正的四组件基础设施与真实模型调用是两种独立的验收维度。
- Kubernetes 只作为后续部署概念，不显示为已部署或已验收。

## 安全和验收

登录使用本项目的 HttpOnly 会话 cookie；写操作仍要验证 CSRF 和 Origin。页面不应把密码、会话令牌或真实模型密钥写进浏览器持久存储，也不能把这些内容写进公开截图或日志。

前端的构建、类型检查、单元测试、匿名界面检查和真实四组件端到端测试分别验证。后端历史证据见 [后端验收报告](TEST_REPORT.md)；只有新一轮实际执行记录才能证明前端联调通过，不能沿用后端测试结果宣称浏览器已通过。
