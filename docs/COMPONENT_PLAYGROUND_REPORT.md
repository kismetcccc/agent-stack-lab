## 实现要点与修复

1. 数据库用历史 v1 标记加 v2 标记，显式创建独立教学表。已知正确的部分 DDL/索引中断可恢复；未知版本、缺失或不兼容结构拒绝，不改写旧表或清空用户数据。实际 MySQL 反射与旧行保留仍需 CI 验证。
2. 审查复现了“已有部分教学表带额外 UNIQUE(name) 却被接受”的问题。现已拒绝不兼容唯一性/约束等结构，SQLite 回归通过；真实 MySQL 测试也包含此冲突和无修改断言，等待执行。
3. Redis 实验使用真实 GET/PTTL 语义和独立命名空间；不可用是明确 503，不用原可选结果缓存的 fail-open 行为冒充成功。
4. Mongo 限制 JSON 字节数、深度、节点、操作符键、非法 UTF-8 和 BSON 整数/浮点边界；写入后读取，不把请求内容直接回显成“已保存”。
5. Kafka 的生产确认和消费者落库回执独立。未确认的发送保留已知 ID，同 ID 重试只查询、不自动重发。消费者先持久化再提交 offset；仅自身回调确认，不拿共享 producer 的其他待发送消息当本消息失败。任务/DLQ topic 不得与固定 lab topic 冲突。
6. 前端审查复现了切页后旧写请求在 CSRF 刷新结束时再次发出的竞态，已用 AbortSignal 和重试前检查修复；JSDOM 回归通过。已经被服务器接受的写入不承诺能因前端取消而撤销。
7. 界面分别说明“真实组件适配器”和“Agent 测试控制器”；组件实验本身不使用模型，不用一个“测试模式”标签暗示数据库都是假的。
