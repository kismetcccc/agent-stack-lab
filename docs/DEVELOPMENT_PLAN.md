# 云端开发任务清单：先把后端做扎实，再交付可学习的项目

更新日期：2026-10-22。范围：学习型 v1；本表是接下来执行的计划，不是已完成声明。

> 优先级调整：**每个后端模块的功能性、调用关系、故障边界与完整文档优先；AI 只验主功能，不继续做精细评分。** 默认 CI 保持 deterministic、零模型凭据。前端是可选观察窗口，不是后端验收的替代品。

架构约束仍以 [Agent.md](../Agent.md) 为准，字段以 [API 契约](API_CONTRACT.md) 为准。本计划先发布到 GitHub，再按“计划 → 实现 → 测试 → 文档 → 更新状态”逐轮执行。若代码已经满足任务，不为凑功能重写；补齐说明、缺失测试和可复核证据即可。

## 1. 有限的 v1 目标与停止条件

### 学习型 v1 完成

满足下列条件后，本轮开发收口，不以不断增加组件或评测数量延长交付：

1. 下表 `BASE-01`、全部 `MOD-*`、`FIX-ENV`、`FIX-01`、`TEST-01..03`、`DOC-01..03`、`OSS-01..02`、`REL-01` 达到“已验收”。审计确认的阻断缺陷须修复并有回归；无缺陷也要留下实际检查结论。
2. 真实 Compose 中可独立用 HTTP 完成注册/登录、带 CSRF 的幂等提交、异步成功/失败、查询事件/尝试/结果、越权拒绝和退出；MySQL/Kafka/MongoDB/Redis/Worker 的正常及必需故障证据齐全；可选精确宕机实验的修复、单元验收与真实运行分别标记。
3. API、Auth、MySQL、Kafka、MongoDB、Redis、Worker 七个模块均按第 4 节模板写明，并与实际函数、测试和接口相互链接。
4. 新读者能依文档完成初始化、启动、正常停止、故障定位与恢复；破坏性重置单独警告。默认流程不需要模型 key，既不默认公开端口，也不修改用户电脑。
5. 最新代码提交的必需 CI 为绿色，报告准确记录 commit、命令、真实依赖/替身、通过/失败/未运行、证据位置；文档链接有效，没有用旧 commit 的结果冒充新代码验收。
6. 已知非生产限制有统一清单；README、文档和 UI 不宣称安全生产部署、端到端 exactly-once、真实模型全栈验收或 Kubernetes 已运行。

### 正式开源发布另有门槛

上述学习型交付可以先完成；**正式采用开源许可证的发布，还必须完成 `OSS-03`：由仓库所有者选择并批准许可证。** 公开仓库不等于批准 MIT、Apache-2.0 或任何其他许可证，不能代替用户作选择。当前先准备依赖/引用来源清单和待决说明，不擅自新增 `LICENSE` 或写“已完整开源授权”。依据：[GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)（2026-10-22 核对；选型说明不是法律意见）。

`LIVE-01` 是独立可选验收，不阻塞 deterministic 后端学习型 v1。若尚未得到私密配置与调用授权，就保留未验收标记，不让云端工作等待本地操作。

## 3. 任务表

### 状态和优先级规则

- 状态只用：**待开始 / 进行中 / 已实现待验收 / 已验收 / 阻塞 / 延期**。任务所涉旧功能已通过，不等于新补文档/审计任务已完成。
- **P0**：正确性、数据权威、授权、安全泄漏或误导性验收陈述；优先处理。
- **P1**：本轮学习型 v1 必需的复现、测试、运维与协作交付。
- **P2**：可选或后续授权范围，不阻塞本轮主链路。
- “证据”先列现存依据/缺口；执行后补实际 commit、测试名和报告，不能仅填“代码已写”。
- “交付文件”中尚不存在的路径是计划产物，**不是可用文件声明**。尽量完善现有文档，避免复制多份互相漂移的契约。

## 4. 每个后端模块必须回答的十个问题

统一写入 `docs/MODULE_CONTRACTS.md` 的对应章节，并链接现有契约；相同字段不在多份文档各写一套。

1. **为什么需要它**：解决哪个真实问题？不用它的最小替代是什么？
2. **职责/不负责什么**：尤其是数据权威与执行权限；模块不等于微服务，也不等于Agent。
3. **输入**：调用者、schema、大小/时间/数量上限、认证上下文、幂等键。
4. **输出**：数据结构、状态码或事件；同步接受与异步成功要分开。
5. **状态/持久化**：表/collection/topic/cache key、主键、索引、TTL、事务/原子范围。
6. **调用链**：入口函数→服务→适配器→下游，指出事务开始/结束与网络调用位置。
7. **失败和降级**：超时、依赖停止、重复、崩溃、坏数据；谁重试、几次、何时停止、谁恢复。
8. **安全与权限**：所有权、CSRF、日志/DTO脱敏、最小访问权、秘密来源；已知不具备的生产防护。
9. **怎么动手验证**：一个正常例子、一个关键故障例子，给命令、预期结果及清理；危险命令单独提示。
10. **证据与下一步**：实际测试/commit链接；未运行、仅模拟、未实现事项显式标记。

### 权威与失败的速查底线

| 模块 | 权威/职责 | 不可突破的验收底线 |
|---|---|---|
| API / Auth | 验证请求和身份、对每个资源授权 | UUID不是授权；缓存命中也不能跳SQL所有权；会话cookie不能替代CSRF |
| MySQL | 用户、任务状态、幂等、Outbox/Inbox、尝试、租约、最终结果引用 | SQL事务失败不能报已接受；未提交结果引用不能报成功 |
| Kafka | 至少一次事件交付、分区/offset | 先持久化Inbox再提交offset；重复允许但不能导致状态回退；不是任务状态库 |
| MongoDB | attempt专属不可变结果/成功后的工具动作 | 持久化失败不能SQL成功；不把孤儿文档当已提交结果；不是第二套状态裁决者 |
| Redis | 可过期提示和结果缓存 | 停机可回源；丢缓存不丢任务；现有缓存可降级不自动意味着未来安全限流也应fail-open |
| Worker | 交付、执行、重试与恢复 | 模型网络调用不占SQL长事务；过期fence不能提交；恢复仍可能重复外部调用 |
| Kubernetes（延期） | 编排进程、服务发现、配置、资源与探针 | 不解决消息幂等、数据库事务或跨库一致性；清单/PVC/Secret不自动证明HA、备份或加密安全 |

## 5. 必须诚实保留的非生产限制

本轮是有真实功能和测试的学习项目，不是上线认证。下面的限制不能靠加一句“production模式”消除：

- **认证与滥用防护**：目前没有登录/注册/任务提交速率限制、邮件验证、找回或MFA；密码哈希和CSRF不等于完整反暴力破解。公网部署前须单独设计限流/配额/可信代理和故障策略。不能无评估就把现有可降级Redis缓存改成唯一安全控制。
- **部署安全**：默认loopback入口、单节点Kafka内网明文、开发凭据、Mongo开发账户不等于生产最小权限/TLS/密钥管理；`LAB_MODE=production` 只代表真实适配器。
- **扩容与数据演进**：单relay/Worker起步，不承诺多副本竞争；当前迁移只含v1初始化，必须说明升级不受支持，未来schema变化需要真实版本迁移，不能修改历史`create_all`冒充升级。
- **可靠性与运维**：没有HA/SLA；一次备份恢复演练不等于灾备保证；已有HTTP指标/trace_id不等于跨服务trace、告警面板或容量规划；资源与延迟数据须实测。
- **结果和审计**：Mongo孤儿清理、失败attempt完整工具轨迹、实时流、DLQ管理/安全人工重放未实现。消费者坏消息停住时宁可保留明确阻塞，不用跳offset或删除数据掩盖问题。
- **真实模型**：连接成功不等于工具与整栈兼容；超时/响应丢失/重试可能重复计费。只读工具、模式标记、预算和提交边界继续保留。

新发现若危及当前本地教学主链路，应进入 `FIX-01`；仅是公网、规模化或未来产品能力，则保留为公开限制，不能无限扩充本轮。

## 7. 每轮实际执行与状态更新方式

1. **选任务**：从依赖已满足的最高优先级任务取一个小而完整的集合；本轮先 `BASE-01 → MOD-*`，随后第一个代码任务为 `FIX-ENV`，再修 `TEST-02` 已确认的实验缺陷。
2. **写计划/预期**：说明改哪些文件、正常/失败分别应发生什么；仅文档审计也说明核对的代码和命令。
3. **实现**：先复用现有实现，只有确认缺陷或必要测试缺口才改代码；不引入另一套架构。
4. **测试**：先针对性检查，再完整所需CI；真实故障只用隔离合成环境。因环境缺失没运行就标“未运行/阻塞”。
5. **同步文档**：接口、配置、示例、架构、运行步骤和限制随同更新；尽量用函数名和文件链接，少写易过期行号。
6. **发布核验**：协调者推送后确认远端目标commit及相应CI；本地校验、上传成功、CI通过分别记录。
7. **更新表和选下一轮**：只有验收满足才改“已验收”；失败保留失败证据，修复后再验。阻塞项继续等待所需授权，其他项照常推进。
