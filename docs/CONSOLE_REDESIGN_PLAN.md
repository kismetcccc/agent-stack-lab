## 1. 本轮要解决什么

把“并排堆放的教学卡片与实验表单”改为“按资源分组、列表优先、按需操作的个人本地控制台”。借鉴 1Panel 的管理界面秩序，不安装 1Panel，也不复制其代码、品牌或素材。

用户目标：组件不再混乱，进入页面就知道 **当前管理什么 → 已有什么数据 → 能做什么 → 操作是否真正生效**。不做上线平台，不新增账号隔离、多租户、配额或管理后台。

已有本机 Edge 实际检查（HEAD 同为 `1fd11480`）进一步确认：环境/标题/返回/共享说明重复占据约半屏；MySQL 常驻表单挤压名称与 ID；Mongo 完整 JSON 列表产生嵌套滚动；主页大卡片与教材同层级；Kafka 历史位于表单和详情下方且选择后详情不自然进入视野；旧任务页也是表单优先。本计划逐项对照这些问题，而不是只改颜色。

**完成边界**：一个统一控制台外壳、一个真实证据总览、四个有各自工作方式的组件页、保留的任务/Agent 与学习入口、完整交互回归和实际截图。全部验收后结束本轮；不延伸为服务器运维平台。

## 3. 冻结范围与不可变条件

### 本轮只做

- 前端导航、页面布局、组件复用、交互状态、视觉和无障碍；必要的前端与浏览器测试及文档。
- 继续使用当前 API、登录/session、CSRF、Origin、分页/输入上限、受限操作和错误语义。
- lab 数据继续本地共享；原任务所有权仍保持原行为。不新增 owner/tenant；也不删除既有授权校验。
- 四组件仍可独立操作，不必先创建 Agent 任务，不需要模型 Key。
- 使用现有路由与深链接。测试只用合成教学数据及已授权的隔离环境。

### 本轮不做

- 不修改后端 API/schema、数据库迁移、Worker 语义、模型配置、Compose 服务和端口。
- 不增加 Docker socket、任意 SQL/Mongo/Redis/shell 终端、服务启停、重启、安装/升级、凭据查看或新的管理命令。
- 不增加 Redis 键扫描/全库列表、Kafka topic/group/offset 管理、消息删除/重放、批量删除、数据导出、服务端搜索或排序。
- 不虚构健康、主机资源图、吞吐、消费延迟、在线用户、任务进度；不为填满界面加入假卡片。
- 不引入新管理 UI 框架、路由框架、图表库或全局状态库来完成这轮重排；优先现有依赖。
- 不调用真实模型、不申请新凭据、不部署公网、不删除卷、不重置已有教学或任务数据。

需要越过任一边界，先单列后续建议，不夹带进本轮。

## 4. 信息架构与路由

桌面左侧为常驻分组导航。分组标题是组织方式，不新增空白中间页面，不要求用户先点一层才能找到组件。

```text
Stack Lab · 本地控制台
  总览                       #playground

  数据存储
    MySQL 记录               #mysql
    MongoDB 文档             #mongo
  缓存
    Redis 键值               #redis
  消息
    Kafka 消息               #kafka[?message=<id>]
  任务
    任务与 Agent             #lab[?task=<id>]

  学习中心（视觉上次级，不在操作区堆教材）
    架构说明                 #overview / #architecture-<component> / #api / #worker
    学习路径                 #learn
    故障实验                 #experiments
```

- 默认入口仍是 `#playground`，展示名称改为“总览”；**不占用已有 `#overview` 架构页**。
- 所有旧 hash 直接访问、刷新、前进/后退继续有效；Kafka message 和 task 参数保持原语义。
- 面包屑统一为“数据存储 / MySQL 记录”等；选中态来自同一个导航配置，不能标题、侧栏和路由各维护一套映射。
- 无效 hash 显示简洁未找到页面及“回到总览”，不静默落入无关学习页。
- 登录仍复用现有能力，入口固定在顶栏；未登录时操作页展示统一的登录状态，不为每个组件再堆一段账号教程。不得通过隐藏登录或跳过认证来减少视觉复杂度。

## 6. 页面规格与有限产品闭环

### 6.1 总览：入口与证据，不做假监控屏

首屏为一张“本地资源”表：组件、用途、现有探测结果/证据、入口。下方只保留必要的运行环境说明和学习入口，去掉四张大型教程卡。

- 复用 `/readyz` 的 `mode/model_mode/dependencies` 与 HTTP 状态；显示“最近检查”时间（浏览器收取响应的时间，不能伪称服务端采样时间）。
- 已核对当前 `/readyz` 仅检查 SQL、Mongo、Kafka，**没有 Redis 总体探针**。Redis 写“未提供总体探针；进入键值页验证”，不能按其他组件结果点绿。
- `production` 只说明真实组件适配器模式，不能翻译成“全部正常”；`in_memory_test_adapter` 明确显示“测试替身”；缺字段、未请求、请求失败均显示“未知/未取得”。
- 503 响应若有有效 JSON，仍展示其依赖结果；网络失败保留旧快照时标“上次检查，非当前状态”。
- API 可响应不等于 Worker 正在工作；Kafka ping 成功不等于消费者收取成功。总览不推断这些结论。
- 不新增 CPU、内存、磁盘、Redis 命中率、Kafka lag 图；不汇总“全系统正常率”。模型模式详细说明留到任务页；四组件页不反复讲 Agent。

闭环：进入总览 → 找到目标组件 → 打开真实资源页；总览失败也能从导航进入页面排查，不阻断全部界面。

### 6.2 MySQL：记录表是主角

- 主视图为全宽表：名称、内容摘要、ID、更新时间、操作；保持服务端分页 10 条与现有总数。
- “新建记录”打开空表单抽屉；点击名称打开详情；“编辑”先按 ID 重新读取再进入编辑态；不把旧列表快照直接当最新记录。
- 详情清晰列出服务端 ID、name、value、created_at、updated_at；原始响应默认折叠为“响应详情”。
- 保存成功显示服务端响应并重新读取列表；写响应与列表回读是两步，不能把前者伪装成后者成功。列表读取失败时保留明确提示。
- 删除对象名称/ID明确确认，取消不发请求；末页删空沿用现有回退页码逻辑。记录已被其他页面删去时显示不存在并刷新，不偷偷重建。
- 不新增 SQL 编辑器、表结构浏览、用户授权或无 API 支持的搜索框。

闭环：列表 → 创建 → 服务端确认 → 列表回读 → 刷新/重开仍存在 → 编辑并读回 → 取消删除无变化 → 确认删除后消失。

### 6.3 MongoDB：文档索引与 JSON 详情

- 主视图为紧凑文档列表，不在每条列表项默认展开整份 JSON；列出 ID、基于当前返回文档计算的字段摘要、更新时间、查看/编辑。
- 点击文档打开更宽详情抽屉；正文以只读格式化 JSON 显示，元数据与 `document` 内容分区。创建/编辑时才出现 JSON 文本编辑器。
- 编辑按钮写“替换文档”；提交前就近保留“完整替换，不是字段合并”的短提示。非法 JSON 显示具体错误且保留草稿。
- 根对象、字节/深度/节点/键名限制保留原契约；长教学解释放帮助，不移走必要字段限制与错误。
- 不增加 Mongo 查询语言、集合管理或 JavaScript 执行。

闭环：文档列表 → 新建 JSON → 列表选择 → 查看完整服务端文档 → 替换字段 → 刷新确认旧字段确实移除 → 逐条确认删除。

### 6.4 Redis：精确键查询，不假装有全库资源列表

- 主视图顶部是“输入键名 → 查询”紧凑工具栏，下方为当前键的服务端快照。**没有全库列表 API，因此不创建假键目录、扫描按钮或“共有 N 个键”。**
- “写入键值”打开含 key/value/TTL 的抽屉；读取视图显示键、实际值、存在状态、TTL 毫秒快照、`observed_at`。
- 参考倒计时次要显示并明确“本地估算”；归零后沿用真实再读。未收到新响应前不能改成“已过期”。
- `exists:false` 是观察时不存在，不保证能区分过期/删除/从未创建；`ttl_ms=-1` 不伪造倒计时；Redis unavailable 不是空值或过期。
- 同名写入就近提示覆盖值并重置 TTL；删除只针对当前明确键名并确认；不触碰任务缓存。

闭环：指定键 → 写入并回读 → 再次读取 TTL → 等待并实际确认不存在 → 同键重新写入 → 确认删除再读。

### 6.5 Kafka：历史列表与两类证据

- 主视图为全宽历史表：消息 ID、key、正文摘要、生产确认、消费者回执、登记时间；不默认把发送表单与大详情面板并排占满页面。
- “发送消息”打开表单抽屉；发送前继续生成并放入 URL 的稳定 ID；确认后打开该消息详情并刷新历史列表。
- 详情按“消息基本信息 / 生产确认 / 消费者回执”分区；实际 key/value、partition、offset 和时间来自对应服务端字段。
- 两类证据分开显示：生产已确认不等于已消费；消费者回执存在也不能强制把 producer 改成已确认。历史回执不等于 broker 目前仍保留正文。
- 继续最多 20 秒自动观察，随后明确“自动观察已暂停，可手动刷新”；不是超时失败，不用百分比进度。关闭详情/切换消息必须清理旧请求与计时器，旧响应不能覆盖新选择。
- 网络中断/未确认时只提供按原 ID 查询；不自动重发。主动“开始新消息”明确是另一次发送，可能重复。
- 保留 `#kafka?message=<id>` 刷新与前进/后退；关闭详情仅改变查看状态，不删除、不撤销发送。

闭环：消息历史 → 发送一次 → 保留 ID → 分别观察 producer 与 consumer → 对照实际收取内容 → 刷新深链仍可查 → 关闭详情回到原列表。

### 6.6 任务与 Agent、学习中心

- 任务页接入同一外壳，列表为主；创建与详情按需打开，保留既有任务状态、事件、尝试、结果与 Agent 动作功能及 task 深链接。
- 模式标识放在任务上下文：deterministic/scripted_test 不说成 LLM 推理；未提交、失败尝试、legacy 结果继续原有语义。
- 不改任务 polling、幂等、所有权、预算与服务端状态机；不新增取消/重试/删除动作。
- 架构、学习路径、故障实验保留完整可达性。学习内容可自有阅读布局，不要求把教材塞进表格。
- 每个组件右上角“帮助”提供：用途、字段限制、最短练习、现有安全边界、相关架构链接；危险边界仍在操作发生处短提示，不只藏在帮助里。

## 7. 统一交互与真实数据规则

1. **首屏先数据**：创建/编辑表单默认关闭；详情按资源选择出现，关闭恢复列表上下文。
2. **状态不混淆**：加载、未登录、未查询、成功空数据、读取失败、旧快照、结果未确认和已确认成功分别呈现。仅成功空响应才显示“暂无数据”。
3. **写入不自动重试**：双击/回车连击只有一次请求；网络不确定时先查事实；离开页面不代表服务端撤销。不能用关闭抽屉取消已送达的写入。
4. **草稿处理**：非空未提交草稿在关闭、切换页面或选择另一对象前提示“继续编辑 / 放弃草稿”；取消保留原内容与焦点。普通字段修改不发 API；已提交但结果不明不通过“放弃草稿”宣布撤销。
5. **弹层行为**：普通未改动抽屉支持 Escape/关闭；有草稿时走同一确认；提交中禁止重复保存/对象删除，显示明确处理中。若允许路由离开，必须沿用现有防旧响应机制并明确请求不一定撤销。
6. **导航中断**：浏览器前进/后退、hash 变化、登录态变化和较新的资源选择都受同一状态约束；过期响应不得回填另一个用户、对象或页面。登录失效沿用当前清理规则，不留前一会话数据。
7. **错误可定位**：保留安全错误文案和 request ID；不显示堆栈、连接串、cookie、CSRF 或秘密。
8. **一致且克制**：成功反馈一处即可，避免 toast、绿条、卡片三次复述；字段约束靠标签/短提示，教材去帮助。
9. **不假装筛选**：本轮不放服务端未支持的搜索/排序控件；若未来加入当前页筛选，必须明确标“仅筛选当前页”，不能伪称全库搜索。本轮无需实现。

### 现有验证入口（实施后运行，当前未运行）

- 前端：`cd frontend && npm ci --no-audit && npm run typecheck && npm test && npm run build`。
- 浏览器：在项目既有、隔离的真实 UI 栈上运行 `TEST_BASE_URL=http://localhost:8081 bash scripts/test-e2e.sh`；沿用 desktop-chromium 1440×1000 与 mobile-chromium 390×844。
- 整体 CI：现有 `checks`、`compose-integration`、`frontend-browser` 三个 job；前端改版不代替既有后端/真实组件/精确宕机窗口回归。
- 正常流截图须使用实际运行界面与合成数据；模拟响应只作明确标注的状态测试，不能当真实四组件验收。
- 不在用户有持久数据的本机为验收故意停库、改配置、删卷。最终本机更新若在既有授权范围内，由维护者单独执行保留数据的更新，并另记运行时 SHA 与验收；计划发布不等于已更新本机。

## 10. 完成定义与停点

本轮只有以下均满足才标“已验收”：

1. 视觉上已经是分组导航、紧凑头部、列表优先、抽屉操作的控制台，而不是原界面改颜色。
2. 四组件各有明确对象与操作闭环，真实写入、回读、失败与不确定状态都能被普通学习者识别。
3. 旧路由、登录安全、任务所有权和 Agent/学习/故障入口不回退；没有新后台能力、凭据或模型调用。
4. 最终提交的必要检查完成；桌面手机截图已逐页复核；未完成项如实标阻塞，不能用“已实现”替代验收。
5. 已有本机栈更新到验收代码，配置与数据保留，实际页面复核通过。
6. 报告写清起点/终点 SHA、实际执行命令、结果、截图和已知限制。之后停止，不自动扩建监控、应用商店、运维终端、多租户或更多组件。
